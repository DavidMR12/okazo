## Nouveaux points

### Corrigé : effacement des données de démonstration trop large (moyenne)

`annonces-api/scripts/seed-demo.mjs:37` (avant correction), désormais `:37-40`.

Risque concret : le script désignait ses comptes par le motif `+2376990%`. Ce motif couvre 100 000 vrais numéros MTN Cameroun. Depuis le 7 novembre, le script peut tourner sur la base de production (`DEMO_AVANT_PREMIERE=oui`). Un `--reset` aurait **supprimé les comptes et les annonces de tout vrai utilisateur** dont le numéro commence par 699 0, et la passe « messagerie uniquement » aurait modifié leurs préférences. Le `--reset` est justement prévu juste avant l'ouverture au public.

Correction : le script ne touche plus que la liste exacte des 48 numéros qu'il crée lui-même (`DEMO_PHONES`), dans les six requêtes (contrôle d'existence, effacement des photos, des annonces et des comptes, passe « messagerie uniquement »).

Preuve : essai sur la base de test jetable, dans une transaction annulée, avec un compte de démonstration et un « vrai abonné » en +237 699 05 55 55 : l'ancien motif trouve **2** comptes, la nouvelle liste **1** seul. `node --check` passe. Le script n'a pas été relancé sur la base de développement, pour ne pas effacer les photos de démonstration du poste.

Reste un risque résiduel faible : ces 48 numéros peuvent appartenir à de vrais abonnés. Un tel abonné qui se connecte pendant que les données de démonstration existent hérite du compte de démonstration. D'où l'importance du `--reset` avant l'ouverture (désormais écrit dans `CLAUDE.md`).

### Corrigé : blocage d'un compte inexistant en erreur 500 (faible, ouvert n° 12 du 2 novembre)

`annonces-api/src/messaging/messaging.service.ts:338-342`.

Risque : erreur serveur (clé étrangère) au lieu d'une réponse claire ; bruit dans les journaux et les futures alertes d'erreurs.

Correction : la cible est cherchée d'abord ; 404 `USER_NOT_FOUND` si elle n'existe pas. Pas de fuite nouvelle : les identifiants de comptes sont déjà publics (profils de vendeurs).

Preuve : test « bloquer un compte inexistant renvoie 404, pas une erreur serveur » dans `annonces-api/test/e2e/security.spec.ts`.

### Ouvert : codes de connexion dans les journaux pendant l'avant-première (moyenne)

`annonces-api/src/config/env.ts:108-109`, `annonces-api/src/auth/sms/console-sms.provider.ts:9`.

Risque : avec `PREVIEW_MODE=true`, chaque code de connexion est écrit en clair, avec le numéro, dans les journaux de l'API. Quiconque lit ces journaux peut se connecter à n'importe quel compte de l'avant-première. Or `CLAUDE.md` prévoit de donner les journaux à l'agent de surveillance du porteur. De plus, Cloudflare Access ferme le site, mais l'API (`api.okazo.org`) doit rester joignable par l'application : elle n'est pas fermée, ce qui reste acceptable puisque les codes ne sortent pas du serveur.

Pourquoi ouvert : c'est un choix délibéré du porteur du 7 novembre pour l'avant-première, pas une erreur de code. Ce qui a été fait : la règle est écrite dans `CLAUDE.md` (journaux = identifiants pendant l'avant-première ; étapes avant l'ouverture).

À décider : ne pas brancher l'agent de surveillance sur les journaux de l'API tant que `PREVIEW_MODE=true`, et repasser à `PREVIEW_MODE=false` avec Infobip dès que le nom d'expéditeur est enregistré.

### Ouvert : images Docker sur des étiquettes mobiles (faible)

`annonces-deploy/compose.yml:104`, `:124`, `:152` ; `annonces-api/Dockerfile:2`, `:13` ; `annonces-web/Dockerfile:2`, `:8`, `:33`.

Risque : `pgvector/pgvector:pg16-trixie`, `redis:7-alpine` et `node:22-bookworm-slim` changent de contenu sans prévenir à chaque reconstruction ; une image compromise ou cassée arriverait sans décision.

Pourquoi ouvert : c'est un compromis. Les étiquettes mobiles apportent aussi les correctifs de sécurité automatiquement. Épingler par empreinte (`@sha256:…`) demande de relever les empreintes sur le serveur et de les mettre à jour chaque mois ; à décider avec la routine de mises à jour mensuelles.

## Contrôlé et sain cette semaine

- **Infobip** (`annonces-api/src/auth/sms/infobip-sms.provider.ts`) : adresse imposée par une expression régulière (`https://xxxxx.api.infobip.com`, pas de SSRF possible par la configuration), délai de 8 s, clé jamais journalisée, message refusé détecté même en réponse 200 ; clé requise au démarrage (`env.ts:105-106`).
- **Configuration de production** : `SMS_PROVIDER=console` reste refusé hors `PREVIEW_MODE` ; `MAIL_PROVIDER=console` toujours refusé ; avertissement au démarrage en avant-première.
- **Secrets** : aucun fichier `.env` suivi par git (seuls les `.env.example`) ; aucune clé, aucun jeton ni clé privée dans les sources ou l'historique ; `annonces-deploy/.env.cloudflare` bien ignoré ; `EXPO_PUBLIC_*` et `NEXT_PUBLIC_*` limités à des adresses et identifiants publics.
- **Site** : redirections après connexion toujours filtrées par `safeReturn` ; redirection de `/recherche` limitée à l'origine du site ; seul `dangerouslySetInnerHTML` : le JSON-LD échappé.
- **API** : aucun `sql.raw`, `sql.identifier` ni `.unsafe(` dans les sources.
- **Infrastructure** : conteneurs de l'API et du site en utilisateur `node`, `no-new-privileges` et `cap_drop: ALL`, aucun port publié, Postgres et Redis sur le réseau `backend` seulement, cloudflared épinglé.
- Les commits du 7 novembre ne touchent ni l'authentification, ni les droits, ni la messagerie, ni les téléversements : les contrôles du 2 novembre sur ces parcours restent valables.

## Pour le porteur, en bref

Cette semaine, j'ai trouvé **4 nouveaux problèmes** et en ai **corrigé 2**, plus 1 problème resté ouvert la semaine dernière.

- Le plus important : le script qui efface les fausses annonces de démonstration aurait aussi pu **effacer les comptes de vrais utilisateurs** dont le numéro commence par 699 0. C'est corrigé et vérifié : il ne touche plus que ses 48 comptes de démonstration.
- Rien de grave n'est ouvert, rien n'a fuité, aucun mot de passe ni clé n'est à changer.

Ce que vous devez faire :
1. Pendant l'avant-première, **ne donnez les journaux de l'API à personne** (ni à votre agent de surveillance) : ils contiennent les codes de connexion.
2. Avant d'ouvrir au public : passez `PREVIEW_MODE=false`, activez Infobip, puis effacez les données de démonstration (`--reset`).
3. Choisissez un fournisseur d'e-mail avant la bêta (point en attente depuis le 2 novembre).
4. Les corrections ne seront en ligne qu'après votre prochain déploiement ; rien n'a été commité.
